## 透明背景导入修复追加检查

2026-10-09：参考任务 `task_814dda832597` 的原始 PNG 为 768×1376 RGBA，包含完全透明、接近透明和半透明像素。PNG 与本地 HTTP 返回的 4,227,072 字节 RGBA 数据完全一致。原工程为 RGB、16 位、Display P3，保存的位置为 `(1920,848)`；因此问题发生在原生写入阶段。

在 Photoshop 27.11.0 中复现：直接把 Uint8 RGBA 写入 16/32 位工程，透明通道被写为不透明。256 个合成样本中，16 位的透明度差异为 192 个；8 位没有差异。修复前报告中的 32 位颜色比较尚未还原线性光，仅以其透明度结果作为复现证据。

`plugin/host.js` 的自动、手动及拖放导入共享同一个 RGBA 写入函数。现在按目标文档位深准备缓冲区：8 位使用 Uint8；16 位使用 Uint16 的 0–32768 范围；32 位使用 Float32，将 sRGB 颜色转为线性光，透明度仍是线性覆盖率。图像自身透明度独立于保存的选区蒙版，导入位置算法保持原规则。SDK 数据格式参考 [Adobe Imaging API](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/imaging)。

原生 `/lab?autorun=1` 新增 8/16/32 位透明渐变往返，总计 11 项；临时工程显式创建为测试需要的位深，避免沿用 Photoshop 最近的建档设置。`/lab?autorun=1&alpha=1` 可单独运行透明度检查，`alpha_task` / `alpha_output` 可在独立临时工程中只读使用既有成片，`alpha_depth` / `alpha_profile` 可匹配目标工程配置；原始成片、已有图层及 PSD 均不改动。
